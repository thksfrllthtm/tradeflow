# East Trans Logistic

Сервис для расчёта растаможки и смет: подбор кода ТН ВЭД (ИИ-агент), пошлины по номенклатуре ЕАЭС, разбор Excel поставщиков.

## Стек
- Backend: Go 1.26, Gin, GORM + pgx, shopspring/decimal, excelize, bcrypt; миграции — CLI golang-migrate (образ `migrate/migrate:v4.18.3`)
- Frontend: React 19, TypeScript, Vite, Vitest, Jspreadsheet CE, pdf.js
- БД: PostgreSQL 17 (локально Docker, прод — Supabase)
- ИИ: DeepSeek (агент ТН ВЭД, подбор цен, керамика), Tavily — поиск, опционально
- Деплой: frontend — Vercel, backend — Render (Docker, free), деплой по push в GitHub

## Команды
- Backend тесты: `cd backend && go test ./...`
- Frontend тесты: `cd frontend && npm test`
- Проверка типов: `cd frontend && npm run check`
- Локально с перезагрузкой: `docker compose -f docker-compose.yml -f docker-compose.dev.yml watch`
- Всё целиком: `docker compose up`
- Новые миграции локально: `docker compose run --rm migrate`

После любых изменений прогоняй тесты той части, которую менял. CI нет, поэтому проверки делаются только руками.

## Структура
- `backend/cmd/` — `server`, `bootstrap-admin` (создание первого администратора), `tnved-agent-eval`
- `backend/internal/http/` — обработчики и маршруты (`server.go`)
- `backend/internal/service/*` — бизнес-логика по модулям
- `backend/internal/repository/` — запросы к БД
- `backend/migrations/` — SQL-миграции golang-migrate: `000031_name.up.sql` + `000031_name.down.sql`
- `frontend/src/features/*` — сметы (`goods`), справочники и номенклатура (`directories`), база решений (`decisions`), керамика, сотрудники, главная, вход (`auth`)
- `frontend/src/shared/*` — общие компоненты, API-клиент, типы
- `docs/STATUS.md` — что работает и чего нет; `docs/DECISIONS.md` — принятые решения. Читай их перед изменением архитектуры.

## Жёсткие правила
- **Миграции:** применённые файлы не менять никогда. Любое изменение схемы — новая пара up/down со следующим номером. На Render миграции применяются при каждом запуске (`deploy/render/entrypoint.sh`), поэтому сломанная миграция ломает прод.
- **Схема только через миграции.** GORM таблицы не создаёт, AutoMigrate не использовать.
- **Деньги и ставки — только `decimal.Decimal`.** Никаких float64 в расчётах, суммах и курсах.
- **Округление** — только через `backend/internal/service/rounding.go` (`RoundMoney` и др.), как в существующем коде расчёта. Не менять без теста.
- **Права проверяются на сервере** (middleware `s.requireUser`, `s.requireAdmin` в `internal/http`). Скрытие кнопки на фронте — не защита.
- Сметы видит только владелец, администратор видит все.
- На проде регистрация закрыта (`ALLOW_REGISTRATION=false`): сотрудников создаёт администратор.

## Авторизация
- Серверные сессии в PostgreSQL, не JWT. Токен в HttpOnly-cookie, в БД хранится только хеш.
- Лимит попыток входа по IP и email (в памяти одного экземпляра backend).
- Роли: `admin` (администратор), `invoicer` (инвойсер), `translator` (переводчик).
- Без входа доступны только health, вход/регистрация и курс НБРК на сегодня (`/api/rates/today`).
- CORS нет: Vercel проксирует `/api/*` на Render, домен один. Не добавлять CORS без необходимости.

## Расчёт растаможки (самая сложная часть)
- Ставки из номенклатуры ЕАЭС. Пошлины: процентные, «не менее», «плюс», за единицу (кг, т, пары, шт). Плюс антидемпинг, СУР, распределение доставки и сбора.
- Ещё **не реализовано:** ставки перечня РК (НДС — только из номенклатуры: процент или освобождение), акциз, ставки за литры и см³.
- Любое изменение расчёта — сначала тест с ожидаемыми цифрами, потом код.

## ИИ-агент
- В тестах используется сценарная модель (`scriptedModel`), а не настоящий DeepSeek. Реальные вызовы в тесты не добавлять.
- `cmd/tnved-agent-eval` тратит платные токены DeepSeek. **Не запускать без моего разрешения.**
- Есть лимиты: Tavily — 1 000 запросов в месяц, плюс дневной лимит запусков агента (`TNVED_AI_DAILY_LIMIT`).

## Разбор Excel
Excel поставщиков бывают грязные: встроенные фото, объединённые ячейки, наборы, разные заголовки. При изменении парсера добавляй тест на реальный пример.

## Известные проблемы
- Render free засыпает, первый запрос после простоя идёт около минуты.
- `docker compose watch` не удаляет в контейнере удалённые файлы: после удаления файлов пересобирай backend.
- Нет восстановления пароля и 2FA.
