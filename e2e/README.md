# E2E-тесты (Playwright)

Проверяют приложение целиком: браузер → frontend → backend → PostgreSQL.

## Запуск

```sh
docker compose up -d          # или ... watch — стек должен работать на http://localhost:5173
cd e2e
npm install
npx playwright install chromium
npm test                      # всё: API + браузер
npm run test:api              # только API (права, расчёт, файлы) — быстро
npm run test:ui               # только браузер
npx playwright test tests/ui/auth.spec.ts --headed   # один файл с окном браузера
npm run report                # HTML-отчёт с трассами упавших тестов
```

Другой адрес: `E2E_BASE_URL=https://... npm test`. Прод не трогать: тесты создают учётки и данные.

## Что важно знать

- **Учётки.** При первом запуске создаётся администратор `e2e-admin@e2e.local` (через
  `bootstrap-admin` в контейнере backend), затем им — `e2e-invoicer`, `e2e-invoicer2`,
  `e2e-translator@e2e.local`. Сессии лежат в `e2e/.auth/` и переиспользуются (вход ограничен
  10 попытками в минуту). Пароль администратора можно задать `E2E_ADMIN_EMAIL` / `E2E_ADMIN_PASSWORD`.
- **Инвойсер у каждого процесса свой** (`e2e-invoicer-w0…w7@e2e.local`, имя то же): сервер при создании
  сметы забирает пустую смету сотрудника и удаляет другие его пустые, поэтому параллельные тесты под
  одной учёткой отнимали бы сметы друг у друга. `as('invoicer')` и `apiAs('invoicer')` подставляют его сами.
- **Уборка.** После прогона удаляются сметы учёток E2E и записи базы решений с «E2E» в тексте.
  Временные сотрудники `e2e-tmp-*` удаляются самими тестами. `E2E_SKIP_TEARDOWN=1` — оставить данные.
- **Платный ИИ не вызывается.** В браузере все запросы к DeepSeek/Gemini (агент, справочник, керамика,
  подбор цен, перевод) по умолчанию получают 503 (`support/fixtures.ts`); тесты ИИ-экранов
  подставляют свои ответы через `page.route`. API-тесты не дёргают эти маршруты под разрешённой ролью.
- **Поиск по базе решений — только цифрами.** Запрос `q` с буквами сервер отправляет в платные
  эмбеддинги Gemini. Тестовые решения получают несуществующие коды `99xxxxxxxx`.
- **Никогда не отправлять импорт базы решений с `replace: true`**: он удаляет всю базу.
- **Общие справочники не перезаписываются**: номенклатура, СУР, ТРОИС, перечень РК в тестах
  загружаются только негативно (битый файл → 400).
- `test.fail()` с комментарием «БАГ: …» — найденный баг приложения: тест станет красным, когда баг исправят,
  тогда `test.fail()` нужно убрать.
