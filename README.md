# Калькулятор предварительного ввоза

Внутренний MVP для сотрудников: сметы товаров (загрузка XLSX, проверка строк, предварительный расчёт растаможки партии, подбор цен под бюджет, экспорт Excel), справочники товаров и кодов ТН ВЭД, сотрудники и роли. Автоматическое получение реальных ставок и выгрузка юридически значимого предложения не реализованы.

## Требования

- Docker Desktop с Docker Compose (самый простой запуск); или Go 1.26+, Node.js 20.19+ и PostgreSQL 17.
- Свободные порты `5173`, `8080` и `5432` для запуска через Docker.

## Запуск через Docker Compose

1. Создайте локальный `.env` из шаблона и задайте **новое** значение `POSTGRES_PASSWORD`. Для Docker Compose `DATABASE_URL` не используется: подключение между контейнерами формируется через сервис `db`. Эта переменная нужна только при локальном запуске API вне Docker.

   ```powershell
   Copy-Item .env.example .env
   ```

2. Примените SQL-миграции и запустите сервисы. Для уже существующего проекта контейнер `migrate` мог завершиться раньше и не запуститься повторно автоматически, поэтому выполняйте миграции явно (команда безопасна при отсутствии новых миграций).

   ```powershell
   docker compose run --rm migrate
   ```

   Для разработки запускайте режим наблюдения:

   ```powershell
   docker compose -f docker-compose.yml -f docker-compose.dev.yml watch
   ```

   Эта команда один раз соберёт dev-образы и запустит сервисы. После этого изменения в `frontend/src` применяются через Vite HMR, а изменения Go-файлов синхронизируются и перезапускают только backend — ручной `docker compose up --build` после каждого изменения не нужен.

   Если нужен обычный запуск без наблюдения файлов, используйте:

   ```powershell
   docker compose up
   ```

3. В отдельном терминале создайте первого сотрудника. Пароль передаётся только окружением и не записывается в проект.

   ```powershell
   $env:BOOTSTRAP_ADMIN_EMAIL='admin@example.com'
   $env:BOOTSTRAP_ADMIN_PASSWORD='создайте-длинный-уникальный-пароль'
   docker compose exec -e BOOTSTRAP_ADMIN_EMAIL -e BOOTSTRAP_ADMIN_PASSWORD backend /app/bootstrap-admin
   ```

4. Откройте http://127.0.0.1:5173 и войдите созданной учётной записью. Явный IPv4-адрес нужен для стабильной работы с Docker Desktop на Windows: в некоторых конфигурациях `localhost` сначала выбирает IPv6 (`::1`) и подключение к опубликованному порту Vite зависает.

Остановить сервисы: `docker compose down`. Чтобы удалить также локальные данные PostgreSQL, выполните `docker compose down -v` (это удалит базу).

### Когда нужна пересборка

- обычные изменения `.tsx`, `.css`, `.html` и `.go` — пересборка не нужна, режим `watch` применяет их сам;
- изменение `package.json`, `package-lock.json`, `vite.config.ts`, `backend/go.mod`, `backend/go.sum`, Dockerfile или добавление системной зависимости — `watch` сам запустит пересборку соответствующего образа;
- новые SQL-миграции — выполните `docker compose run --rm migrate`, затем продолжайте работу в `watch`;
- вручную запускать `docker compose up --build` нужно только если не используете dev-команду `watch` или хотите проверить production-образ.

## Регистрация, вход и выход

На экране входа сотрудник может создать обычный аккаунт по имени, email и паролю. Регистрация сразу создаёт серверную сессию и открывает список собственных смет. Роль, права и владельца сметы нельзя передать из формы регистрации. Email нормализуется (пробелы по краям удаляются, регистр приводится к нижнему), пароль не обрезается и хранится только как bcrypt-хеш; минимальная длина — 8 символов, пробелы разрешены. Для паролей длиннее 72 байт (ограничение bcrypt) перед bcrypt вычисляется SHA-256, поэтому длинная фраза не теряется.

Сессия хранится в непрозрачной HttpOnly-cookie и проверяется сервером при каждом защищённом запросе. Токены и пароли не попадают в `localStorage` или `sessionStorage`; в `sessionStorage` используется только техническая отметка, чтобы после обновления показать сообщение об истёкшей сессии. Кнопка «Выйти» удаляет сессию на сервере и очищает cookie. После истечения TTL приложение возвращает на форму входа с сообщением «Сессия завершена. Войдите снова».

Регистрация и вход ограничены десятью попытками в минуту на сочетание IP и email в одном экземпляре backend. Для нескольких экземпляров сервера перед публикацией нужен общий rate limiter (например, Redis или ограничение на reverse proxy). Подтверждение email, восстановление пароля, 2FA и CAPTCHA пока не входят в MVP; при публикации приложения доступ к нему должен оставаться во внутренней сети.

Миграции лежат в `backend/migrations`; `000022_drop_legacy_module` удаляет таблицы старого модуля импорта, классификатора и ИИ-анализа товаров. На существующей базе сначала примените миграции (`docker compose run --rm migrate`), затем пересоберите backend. Первый служебный аккаунт создаётся только командой `bootstrap-admin`; стандартного пароля в проекте нет.

Для интеграционной проверки API используйте `POST /api/auth/register` с JSON `{ "name": "Имя", "email": "employee@example.com", "password": "не менее 8 символов" }`. Успешный ответ — `201` и HttpOnly-cookie; повторный email — `409`, неверные поля — `400`, превышение лимита попыток — `429`. Вход выполняется через `POST /api/auth/login`, выход — через `POST /api/auth/logout`.

```powershell
Set-Location backend
```


## Сметы товаров

В верхней панели откройте «Сметы» — это сметы товаров (таблица `gloves_copy_estimates`,
API `/api/gloves-copy`; названия остались от первой версии калькулятора для перчаток). XLSX можно
загрузить в этот раздел, выбрать лист/строку заголовков и сопоставить колонки
«наименование», «пары», «места», «пар в месте», «брутто» и «нетто». Пустые
значения остаются для ручного ввода. Одна строка «места × пар в месте» уже
означает количество пар — деления на 2 нет.
Автоматического выбора колонок нет: после загрузки все назначения начинаются с
«Не использовать», и оператор вручную выбирает смысл только нужных колонок
прямо в заголовке Excel-подобной таблицы. В этой же таблице флажком «Импорт»
можно снять лишние строки; исходные значения при этом сохраняются в снимке.
В параметрах расчёта можно указать дату и страну происхождения партии; страна
не подставляется автоматически.
После загрузки исходные строки и выбранное сопоставление сохраняются в снимке
источника отдельно от редактируемых строк; исходный XLSX при этом не изменяется.
Пустые строки и строки, похожие на итоги (`Итого`, `Всего`, `Total`, `合计`,
`总计`), автоматически исключаются из товаров и отмечаются предупреждением.
После выбора другого листа или строк можно нажать «Перечитать лист» — текущие
строки будут заменены после явного подтверждения.

Экран работает по шагам: на странице «Файл и колонки» загружается XLSX и для
каждой колонки выбирается смысл (ненужные оставляются «Не использовать»);
кнопка «Применить и перейти к проверке» открывает отдельную страницу строк.
На странице «Проверка строк» выполняются исправления и выбор карточек, а блок
параметров расчёта (дата, курсы, доставка и сбор) расположен внизу перед
кнопкой расчёта. После «Рассчитать и открыть результат» открывается отдельная
страница итогов. Назад к предыдущему шагу можно вернуться без потери данных.

После загрузки выберите строки в колонке «База», найдите карточку в справочнике
и нажмите «Применить». Сервер повторно проверяет выбранный идентификатор и
берёт код, пошлину и НДС только из активной карточки; присланный из браузера
снимок ставки не является доверенным. ИТС карточки подставляется как
значение по умолчанию, но его можно явно изменить для одной строки, не меняя
справочник. Без карточки строка остаётся со статусом «Проверить».

Базовая стоимость строки = ИТС строки (по умолчанию ИТС
карточки) × нетто (кг). Для строки с парами цена пары получается делением
базовой стоимости на пары, округляется до 4 знаков, а итоговая стоимость
строки считается как округлённая цена пары × количество пар. Если нетто нет, сервер считает его как
`брутто − места × вес упаковки` (по умолчанию 0,3 кг/место). Доставка вводится
одной суммой за всю партию (или вагоны × тариф) и автоматически распределяется
по положительному брутто; она не умножается на каждую строку. Флажок «Доставка
в базу» отдельно определяет, какие доли входят в таможенную стоимость (по
умолчанию выключен); сама доставка в расходах партии учитывается один раз.
Если брутто отсутствует или автоматическая доля не подходит, в колонке «Доля
доставки, USD» можно вручную задать долю для каждой строки; сумма ручных долей
должна совпасть с общей доставкой.
Количество вагонов вводится вручную; тариф по умолчанию — 420 USD за вагон,
но сам вагон не подставляется автоматически.
Пошлина, НДС и
сбор считаются по снимку карточки, неизвестные ставки не превращаются в ноль.

Кнопка «Рассчитать» выполняет один запрос, а «Экспорт Excel» формирует
помеченный как предварительный файл. Смета сохраняется на сервер сама, через
1,5 с после последней правки (`PATCH /api/gloves-copy/estimates/:id/draft`): уходят
только изменённые части — поля параметров, строки текстом без фото, результат и фото
изменённых строк (порциями до ~3 МБ). Фото строк хранятся отдельно, в таблице
`goods_estimate_photos`. Кнопки «Сохранить черновик» / «Сохранить результат» сохраняют
сразу. Копия черновика и результата хранится и в браузере: если сервер был недоступен,
при следующем открытии изменения из браузера сами уходят на сервер. Один запрос
сохранения ограничен 32 МБ, расчёт/экспорт — 16 МБ (фотографии в них не отправляются), XLSX — 100 МБ,
до 5 000 строк на лист и до 10 000 строк в книге. Поддерживаются встроенные JPG,
JPEG и PNG; другие форматы пропускаются с предупреждением. Если в Excel фото
нет, его можно добавить к строке вручную (JPG/PNG до 5 МБ); URL не скачиваются.
Количества пар,
мест и пар в месте должны быть целыми; дробное автоматически выведенное число
мест требует исправления. Раздел не получает ставки из интернета
и не выполняет классификацию ИИ. ИИ (DeepSeek, ключ `DEEPSEEK_API_KEY`) используется
только кнопкой «Подобрать с ИИ» на этапе результата: он оценивает и объясняет цену каждого товара
(разные товары одного кода — разные цены, один товар в разных строках — одна цена), а сумму
под бюджет подбирает та же математика, что и у кнопки «Подобрать цены».

Защищённые маршруты: `POST /api/gloves/parse-xlsx`, `POST /api/gloves/calculate`,
`POST /api/gloves/export` (общее ядро разбора и расчёта), сметы — `/api/gloves-copy/estimates`,
подбор цен — `POST /api/estimates/price-weights` и `POST /api/estimates/price-history`.

## Керамика: наименование и цена

Отдельный модуль (`/ceramics`), не связанный со сметами, пошлинами, НДС и доставкой. По марке,
китайскому наименованию и фото из Excel клиента подбирает наименование и цену из своей базы
(таблица `ceramic_products`, миграция `000025_ceramics`). В базе у марки три поля: наименование,
марка и цена; наименование пишется как «Керамическая фруктовница 7 дюймов для взрослых/ 成年人陶瓷盘7高脚水果盘».
Тип («Керамическая фруктовница для взрослых»), размер (7") и китайскую часть backend выделяет из
наименования сам при каждом сохранении — по ним подбирается цена.

1. Точная марка в базе — наименование и цена берутся из записи, ИИ не вызывается.
2. Неизвестная марка: размер — из китайского названия (`7寸`, `七寸`, `20cm`, число без единицы
   `7高脚` — как предположение), подтверждение — по серии известных марок (`721-{SIZE}`) или по такому же
   китайскому названию в базе; тип — по такому же китайскому названию (без чисел) в базе, иначе ИИ в два
   этапа (кандидаты из типов базы → сравнение похожих типов). Ответ ИИ вне списка типов не принимается.
3. Цена — самая частая цена записей с тем же типом и размером; ничья или отсутствующий размер —
   «Требует проверки». Средняя и цена соседнего размера не используются.
4. Наименование новой марки собирается так же, как у других марок этого типа, плюс китайское название
   клиента; в базу оно попадает только после «Подтвердить и сохранить».

ИИ — любой OpenAI-совместимый Chat Completions API: `CERAMICS_AI_API_KEY`, `CERAMICS_AI_BASE_URL`,
`CERAMICS_AI_MODEL` (пустые — тот же DeepSeek), `CERAMICS_AI_VISION` (по умолчанию `true`: фото
отправляется модели; `deepseek-flash` изображения принимает). Маршруты: `/api/ceramics/*`
(`lookup`, `analyze`, `price`, `products`, `products/import`, `types`, `status`); удаление марок
и импорт базы — только администратор.

## Структура кода

Frontend (`frontend/src`) разложен по функциям; импорты между областями — через `@/` (= `src/`),
внутри области — относительные. CSS лежит рядом с компонентом, общие стили — в `styles/` своей области.

```text
app/                         App: проверка сессии, выбор страницы по адресу, перенаправления
shared/                      то, что нужно всем: api/client.ts, router (адреса страниц), components/AppHeader
                             (общая шапка), types, lib, hooks, styles (base, app-shell)
features/auth/               вход и регистрация
features/directories/        справочники: tnved/ (коды ТН ВЭД), products/ (карточки товаров)
features/estimates/
  shared/                    типы, calculatorApi (разбор XLSX, расчёт, экспорт), подбор цен под бюджет,
                             хранилище фото, операции со строками, общие стили
  goods/                     «Сметы товаров» (API /api/gloves-copy)
    calculator/              калькулятор: состояние и шаги
    components/              этапы (ImportStep, ReviewStep, ResultStep) и окна
    lib/, hooks/             хранилище черновика, сопоставление колонок, хуки
features/home/               главная: быстрые действия, коды на проверке, последние сметы
features/employees/          сотрудники и роли (только администратор)
features/ceramics/           подбор наименования и цены керамики (отдельно от смет; API /api/ceramics)
```

Адреса страниц (`shared/router/router.ts`; старые ссылки вида `/#gloves-copy` открываются и заменяются на новые):

| Адрес | Страница |
|---|---|
| `/` | Главная: новая смета, проверка кодов ТН ВЭД, керамика, последние сметы; у администратора — сколько кодов ждут проверки |
| `/estimates/goods`, `/estimates/goods/12` | Сметы товаров, смета № 12 |
| `/directory/products` | Справочник товаров |
| `/directory/tnved` | Справочник ТН ВЭД (`?check=1` — сразу открыть проверку кодов, `?status=needs_review` — только коды на проверке) |
| `/employees` | Сотрудники (только администратор) |
| `/login`, `/register` | Вход и регистрация |

Backend (`backend/internal`): `http/` — обработчики по доменам (`*_handler.go`, маршруты в
`server.go`), `service/` — бизнес-логика и расчёты, `repository/` — GORM-модели и запросы по
таблицам, `config/` — настройки. Точки входа — `backend/cmd/*`, миграции — `backend/migrations`.

## Миграции

SQL-миграции находятся в `backend/migrations`. GORM используется для запросов, но не выполняет схему через `AutoMigrate`.

Применить миграции вручную:

```powershell
docker compose run --rm migrate
```

Откатить последнюю миграцию:

```powershell
docker run --rm -v "${PWD}\backend\migrations:/migrations" migrate/migrate:v4.18.3 -path=/migrations -database="$env:DATABASE_URL" down 1
```

`COOKIE_SECURE=true` обязателен при работе за HTTPS; для `http://localhost` оставьте `false`.

## Справочник ТН ВЭД (операторские записи)

В верхней навигации доступна отдельная страница «Справочник ТН ВЭД». В первой версии используется категория «Перчатки»: сотрудник вручную добавляет понятное название, 10-значный код и синонимы на русском, китайском и английском. Поиск работает по коду, названию и синонимам; статус можно фильтровать как «Требует проверки» или «Проверено оператором».

Справочник хранится в таблице `tnved_directory_entries`. Это не официальное описание и не подтверждение актуальности кода. Один код может иметь несколько названий; дубликат активной пары «код + категория + название» отклоняется (HTTP `409`). Удаление заменено архивированием, поэтому история сохраняется. Изменения записи не обновляют уже сохранённые сметы.

### Выгрузка и загрузка справочников (администратор)

На страницах «Справочник ТН ВЭД» и «Справочник товаров» у администратора есть кнопки «Выгрузить» и «Загрузить»: справочник переносится между серверами или правится в Excel целиком. Выгрузка — все действующие (не архивные) записи в XLSX. Загрузка сопоставляет строки с действующими записями по тем же ключам, что и уникальность: ТН ВЭД — код + категория + описание, товары — категория + наименование; совпавшие обновляются (или пропускаются, если снять «Обновлять записи, которые уже есть»), остальные добавляются. Весь файл проверяется заранее: при ошибке хотя бы в одной строке ничего не сохраняется, а список строк с причинами показывается на странице. Колонка, которой нет в файле, не меняет сохранённое значение. Код ТН ВЭД товара ищется среди карточек ТН ВЭД, поэтому сначала загружается справочник ТН ВЭД. Маршруты: `GET /api/tnved-directory/export`, `POST /api/tnved-directory/import`, `GET /api/product-directory/export`, `POST /api/product-directory/import` (`?update=false` — только новые записи).

### Проверка кодов перед расчётом

Кнопка «Проверить коды» на странице «Справочник ТН ВЭД» доступна всем сотрудникам: в поле вставляется колонка кодов, скопированная из Excel (повторы, заголовок колонки, пробелы внутри кода допускаются; код из 9 цифр считается кодом с потерянным в Excel ведущим нулём). Список сверяется со всем справочником, включая архив: сверху — коды, которых нет, затем коды, которые есть только в архиве, затем найденные. Недостающий код добавляется кнопкой «Добавить» (карточка открывается с уже заполненным кодом), архивный восстанавливает администратор; после сохранения проверка повторяется.

Добавлять коды ТН ВЭД могут администратор и инвойсер (`POST /api/tnved-directory`). Код, добавленный инвойсером, всегда сохраняется со статусом «Требует проверки»: в форме «Проверено» недоступно, а сервер принудительно сбрасывает статус, даже если его прислали. Отметить код проверенным, править существующие записи, архивировать и загружать Excel может только администратор. «Копировать недостающие» кладёт список кодов в буфер обмена, чтобы вставить его обратно в Excel. Проверка работает на фронтенде поверх `GET /api/tnved-directory?includeArchived=true`, отдельного маршрута нет.

На этапе «Проверка строк» сметы кнопка кода ТН ВЭД ищет активные записи по названию и синонимам. В строку сметы сохраняется снимок выбранной записи и её идентификатор, поэтому последующие правки справочника не меняют старую смету. Неуказанная ставка отображается как «Не указана», `0` хранится отдельно и требует осознанного ввода. Для пошлины доступны процентная, за единицу и комбинированная «не менее» ставки; для НДС — процентная, освобождение с основанием или неизвестная. Значение `12` означает 12%; принимаются точка и запятая. ИТС компании хранится отдельно и используется в формуле `USD = ИТС × вес нетто (кг)`, цена пары вычисляется только в контексте партии. Даты действия и источник ставки сохраняются отдельно для пошлины и НДС.

API (требует сессию): `GET /api/tnved-directory?q=&category=Перчатки&status=all&includeArchived=false`, `POST /api/tnved-directory`, `PATCH /api/tnved-directory/:id`, `POST /api/tnved-directory/:id/copy`, `POST /api/tnved-directory/:id/archive`, `POST /api/tnved-directory/:id/restore`. Поля `duty` и `vat` структурированы (`type`, `percent`, `amount`, `currency`, `unit`/`basis`, `checkedAt`, даты действия, источник); неизвестное значение передаётся пустыми полями, а не нулём.

Чтобы добавить первую карточку: войдите, откройте в верхней навигации «Справочник ТН ВЭД» → «Добавить запись», выберите категорию «Перчатки» и заполните русское название и 10 цифр кода. Китайское название и ИТС можно указать отдельно (например, `0,65`); пошлину и НДС оставьте «Не указана/Не указан», если источник ещё не проверен. Сохраните запись со статусом «Требует проверки». Код `4015190000` из примера пользователя является только предоставленным значением и не считается подтверждённым автоматически.
