# Калькулятор предварительного ввоза

Внутренний MVP для сотрудников: регистрация и вход, создание/редактирование предварительных смет, импорт позиций из XLSX, операторский справочник ТН ВЭД для перчаток и предварительный расчёт растаможки партии. Автоматическое получение реальных ставок и выгрузка юридически значимого предложения ещё не реализованы.

## Требования

- Docker Desktop с Docker Compose (самый простой запуск); или Go 1.26+, Node.js 20.19+ и PostgreSQL 17.
- Свободные порты `5173`, `8080` и `5432` для запуска через Docker.

## Запуск через Docker Compose

1. Создайте локальный `.env` из шаблона и задайте **новое** значение `POSTGRES_PASSWORD`. Для Docker Compose `DATABASE_URL` не используется: подключение между контейнерами формируется через сервис `db`. Эта переменная нужна только при локальном запуске API вне Docker.

   ```powershell
   Copy-Item .env.example .env
   ```

2. Примените SQL-миграции и запустите сервисы. Для уже существующего проекта контейнер `migrate` мог завершиться раньше и не запуститься повторно автоматически, поэтому выполняйте миграции явно (команда безопасна при отсутствии новых миграций).

   ```powershell
   docker compose run --rm migrate
   ```

   Для разработки запускайте режим наблюдения:

   ```powershell
   docker compose -f docker-compose.yml -f docker-compose.dev.yml watch
   ```

   Эта команда один раз соберёт dev-образы и запустит сервисы. После этого изменения в `frontend/src` применяются через Vite HMR, а изменения Go-файлов синхронизируются и перезапускают только backend — ручной `docker compose up --build` после каждого изменения не нужен.

   Если нужен обычный запуск без наблюдения файлов, используйте:

   ```powershell
   docker compose up
   ```

3. В отдельном терминале создайте первого сотрудника. Пароль передаётся только окружением и не записывается в проект.

   ```powershell
   $env:BOOTSTRAP_ADMIN_EMAIL='admin@example.com'
   $env:BOOTSTRAP_ADMIN_PASSWORD='создайте-длинный-уникальный-пароль'
   docker compose exec -e BOOTSTRAP_ADMIN_EMAIL -e BOOTSTRAP_ADMIN_PASSWORD backend /app/bootstrap-admin
   ```

4. Откройте http://127.0.0.1:5173 и войдите созданной учётной записью. Явный IPv4-адрес нужен для стабильной работы с Docker Desktop на Windows: в некоторых конфигурациях `localhost` сначала выбирает IPv6 (`::1`) и подключение к опубликованному порту Vite зависает.

Остановить сервисы: `docker compose down`. Чтобы удалить также локальные данные PostgreSQL, выполните `docker compose down -v` (это удалит базу).

### Когда нужна пересборка

- обычные изменения `.tsx`, `.css`, `.html` и `.go` — пересборка не нужна, режим `watch` применяет их сам;
- изменение `package.json`, `package-lock.json`, `vite.config.ts`, `backend/go.mod`, `backend/go.sum`, Dockerfile или добавление системной зависимости — `watch` сам запустит пересборку соответствующего образа;
- новые SQL-миграции — выполните `docker compose run --rm migrate`, затем продолжайте работу в `watch`;
- вручную запускать `docker compose up --build` нужно только если не используете dev-команду `watch` или хотите проверить production-образ.

## Регистрация, вход и выход

На экране входа сотрудник может создать обычный аккаунт по имени, email и паролю. Регистрация сразу создаёт серверную сессию и открывает список собственных смет. Роль, права и владельца сметы нельзя передать из формы регистрации. Email нормализуется (пробелы по краям удаляются, регистр приводится к нижнему), пароль не обрезается и хранится только как bcrypt-хеш; минимальная длина — 8 символов, пробелы разрешены. Для паролей длиннее 72 байт (ограничение bcrypt) перед bcrypt вычисляется SHA-256, поэтому длинная фраза не теряется.

Сессия хранится в непрозрачной HttpOnly-cookie и проверяется сервером при каждом защищённом запросе. Токены и пароли не попадают в `localStorage` или `sessionStorage`; в `sessionStorage` используется только техническая отметка, чтобы после обновления показать сообщение об истёкшей сессии. Кнопка «Выйти» удаляет сессию на сервере и очищает cookie. После истечения TTL приложение возвращает на форму входа с сообщением «Сессия завершена. Войдите снова».

Регистрация и вход ограничены десятью попытками в минуту на сочетание IP и email в одном экземпляре backend. Для нескольких экземпляров сервера перед публикацией нужен общий rate limiter (например, Redis или ограничение на reverse proxy). Подтверждение email, восстановление пароля, 2FA и CAPTCHA пока не входят в MVP; при публикации приложения доступ к нему должен оставаться во внутренней сети.

Миграция `000008_user_names` добавляет имя пользователя и закрепляет уникальность нормализованного email. Миграции `000009_tnved_directory`, `000010_tnved_directory_rates_snapshot` и `000011_tnved_directory_rate_checked_at` добавляют операторский справочник перчаток, снимок выбранной записи в товаре и отдельную дату проверки ставок. Миграция `000012_customs_calculation` добавляет сохранённый предварительный расчёт партии, `000013_glove_quantities` — отдельные поля пар, мест и пар в месте для файлов поставщика без цен, а `000014_calculation_revisions` — явный режим доставки, сохранённые итоги/входы и историю ревизий расчёта. На существующей базе сначала примените миграции (`docker compose run --rm migrate`), затем пересоберите backend. Если в старой базе уже есть два email, отличающиеся только регистром или внешними пробелами, миграция остановится без удаления данных — сначала объедините такие записи вручную. Первый служебный аккаунт по-прежнему создаётся только командой `bootstrap-admin`; стандартного пароля в проекте нет.

Для интеграционной проверки API используйте `POST /api/auth/register` с JSON `{ "name": "Имя", "email": "employee@example.com", "password": "не менее 8 символов" }`. Успешный ответ — `201` и HttpOnly-cookie; повторный email — `409`, неверные поля — `400`, превышение лимита попыток — `429`. Вход выполняется через `POST /api/auth/login`, выход — через `POST /api/auth/logout`.

## Отдельный расчёт перчаток

В верхней панели приложения откройте «Перчатки». Это самостоятельный рабочий
черновик сотрудника, не связанный со стадией 3 обычной сметы. XLSX можно
загрузить в этот раздел, выбрать лист/строку заголовков и сопоставить колонки
«наименование», «пары», «места», «пар в месте», «брутто» и «нетто». Пустые
значения остаются для ручного ввода. Одна строка «места × пар в месте» уже
означает количество пар — деления на 2 нет.
Автоматического выбора колонок нет: после загрузки все назначения начинаются с
«Не использовать», и оператор вручную выбирает смысл только нужных колонок
прямо в заголовке Excel-подобной таблицы. В этой же таблице флажком «Импорт»
можно снять лишние строки; исходные значения при этом сохраняются в снимке.
В параметрах расчёта можно указать дату и страну происхождения партии; страна
не подставляется автоматически.
После загрузки исходные строки и выбранное сопоставление сохраняются в снимке
источника отдельно от редактируемых строк; исходный XLSX при этом не изменяется.
Пустые строки и строки, похожие на итоги (`Итого`, `Всего`, `Total`, `合计`,
`总计`), автоматически исключаются из товаров и отмечаются предупреждением.
После выбора другого листа или строк можно нажать «Перечитать лист» — текущие
строки будут заменены после явного подтверждения.

Экран работает по шагам: на странице «Файл и колонки» загружается XLSX и для
каждой колонки выбирается смысл (ненужные оставляются «Не использовать»);
кнопка «Применить и перейти к проверке» открывает отдельную страницу строк.
На странице «Проверка строк» выполняются исправления и выбор карточек, а блок
параметров расчёта (дата, курсы, доставка и сбор) расположен внизу перед
кнопкой расчёта. После «Рассчитать и открыть результат» открывается отдельная
страница итогов. Назад к предыдущему шагу можно вернуться без потери данных.

После загрузки выберите строки в колонке «База», найдите карточку в справочнике
и нажмите «Применить». Сервер повторно проверяет выбранный идентификатор и
берёт код, пошлину и НДС только из активной карточки; присланный из браузера
снимок ставки не является доверенным. ИТС карточки подставляется как
значение по умолчанию, но его можно явно изменить для одной строки, не меняя
справочник. Без карточки строка остаётся со статусом «Проверить».

Базовая стоимость строки = ИТС строки (по умолчанию ИТС
карточки) × нетто (кг). Для строки с парами цена пары получается делением
базовой стоимости на пары, округляется до 4 знаков, а итоговая стоимость
строки считается как округлённая цена пары × количество пар. Если нетто нет, сервер считает его как
`брутто − места × вес упаковки` (по умолчанию 0,3 кг/место). Доставка вводится
одной суммой за всю партию (или вагоны × тариф) и автоматически распределяется
по положительному брутто; она не умножается на каждую строку. Флажок «Доставка
в базу» отдельно определяет, какие доли входят в таможенную стоимость (по
умолчанию выключен); сама доставка в расходах партии учитывается один раз.
Если брутто отсутствует или автоматическая доля не подходит, в колонке «Доля
доставки, USD» можно вручную задать долю для каждой строки; сумма ручных долей
должна совпасть с общей доставкой.
Количество вагонов вводится вручную; тариф по умолчанию — 420 USD за вагон,
но сам вагон не подставляется автоматически.
Пошлина, НДС и
сбор считаются по снимку карточки, неизвестные ставки не превращаются в ноль.

Кнопка «Рассчитать» выполняет один запрос, а «Экспорт Excel» формирует
помеченный как предварительный файл. Кнопка «Сохранить черновик» сохраняет
введённые данные на сервере для текущего сотрудника даже до расчёта; изменения
также остаются локально в браузере при редактировании. При обновлении более
свежая локальная версия не затирается устаревшим серверным черновиком;
встроенные фотографии сохраняются локально и могут быть исключены из localStorage
при превышении лимита браузера. Запрос сохранения черновика ограничен 64 МБ,
расчёт/экспорт — 16 МБ (фотографии в них не отправляются), XLSX — 50 МБ,
до 5 000 строк на лист и до 10 000 строк в книге. Поддерживаются встроенные JPG,
JPEG и PNG; другие форматы пропускаются с предупреждением. Если в Excel фото
нет, его можно добавить к строке вручную (JPG/PNG до 5 МБ); URL не скачиваются.
Количества пар,
мест и пар в месте должны быть целыми; дробное автоматически выведенное число
мест требует исправления. Раздел не получает ставки из интернета
и не выполняет классификацию ИИ.

Для существующей базы примените новую миграцию `000015_gloves_calculation_drafts`
командой `docker compose run --rm migrate`, затем пересоберите backend.
Защищённые маршруты отдельного раздела: `POST /api/gloves/parse-xlsx`,
`GET/PUT /api/gloves/draft`, `POST /api/gloves/calculate` и
`POST /api/gloves/export`.

## Структура кода

Frontend (`frontend/src`) разложен по функциям; импорты между областями — через `@/` (= `src/`),
внутри области — относительные. CSS лежит рядом с компонентом, общие стили — в `styles/` своей области.

```text
app/                         App: проверка сессии, выбор страницы по адресу, перенаправления
shared/                      то, что нужно всем: api/client.ts, router (адреса страниц), components/AppHeader
                             (общая шапка), types, lib, hooks, styles (base, app-shell)
features/auth/               вход и регистрация
features/directories/        справочники: tnved/ (коды ТН ВЭД), products/ (карточки товаров)
features/estimates/
  shared/                    общее для обоих калькуляторов: типы, calculatorApi (разбор XLSX, расчёт,
                             экспорт), хранилище фото, операции со строками, общие стили
  goods/                     «Сметы товаров» (главная, API /api/gloves-copy)
  gloves/                    «Сметы перчаток» (API /api/gloves)
    <feature>/calculator/    калькулятор: состояние и шаги
    <feature>/components/    этапы (ImportStep, ReviewStep, ResultStep) и окна
    <feature>/lib, hooks/    хранилище черновика, сопоставление колонок, хуки
```

Адреса страниц (`shared/router/router.ts`; старые ссылки вида `/#gloves-copy` открываются и заменяются на новые):

| Адрес | Страница |
|---|---|
| `/estimates/goods`, `/estimates/goods/12` | Сметы товаров (главная), смета № 12 |
| `/estimates/gloves`, `/estimates/gloves/7` | Сметы перчаток |
| `/directory/products` | Справочник товаров |
| `/directory/tnved` | Справочник ТН ВЭД |
| `/login`, `/register` | Вход и регистрация |

Backend (`backend/internal`): `http/` — обработчики по доменам (`*_handler.go`, маршруты в
`server.go`), `service/` — бизнес-логика и расчёты, `repository/` — GORM-модели и запросы по
таблицам, `config/` — настройки. Точки входа — `backend/cmd/*`, миграции — `backend/migrations`.

## Миграции

SQL-миграции находятся в `backend/migrations`. GORM используется для запросов, но не выполняет схему через `AutoMigrate`.

Применить миграции вручную:

```powershell
docker compose run --rm migrate
```

Откатить последнюю миграцию:

```powershell
docker run --rm -v "${PWD}\backend\migrations:/migrations" migrate/migrate:v4.18.3 -path=/migrations -database="$env:DATABASE_URL" down 1
```

`COOKIE_SECURE=true` обязателен при работе за HTTPS; для `http://localhost` оставьте `false`.

## Импорт XLSX (этап 2)

Исходный XLSX и изображения хранятся в закрытой серверной папке (`FILE_STORAGE_DIR`), не в frontend и не по публичному URL. Доступ к связанным изображениям требует активной сессии сотрудника и проверяется сервером по владельцу сметы.

Поддерживаемый входной формат:

- обычный `.xlsx`, до 50 МБ и до 100 МБ после распаковки;
- не более 5 000 строк на одном листе, 10 000 строк на книге и 100 колонок в строке;
- сотрудник выбирает лист, строку заголовков и начало данных; строки до начала данных остаются только частью рабочей копии;
- над каждой колонкой назначается поле системы: название от поставщика, перевод, артикул, пары, места, пар в месте, вес брутто/нетто, материал, характеристики, фото или дополнительное поле. Ценовые поля остаются только для совместимости со старыми файлами и для этого сценария не требуются;
- эвристическое распознавание заголовков является подсказкой. Повторное назначение одного стандартного поля блокируется до исправления конфликта;
- встроенные изображения JPG/PNG, привязанные к той же строке, что и товар; также JPG/PNG до 5 МБ можно загрузить вручную для сохранённой позиции.

Ограничения и правила безопасности:

- отклоняются повреждённые файлы, файлы с макросами (`vbaProject`), внешними связями, чрезмерным размером или числом строк;
- файл читается как данные: макросы, формулы и внешние связи не исполняются. Формула без сохранённого значения отмечается как требующая исправления;
- `,` и `.` в числах обрабатываются только при однозначном формате. Например, `1,000` требует ручного исправления; `1 234,50` допустимо;
- пустые строки и строки, похожие на «Итого»/«Всего», не выбираются автоматически. Их можно увидеть и изменить выбор до подтверждения;
- если старый файл содержит цену, она вычисляется из суммы и количества только при положительном количестве; исходные значения сохраняются. Расхождение суммы с `количество × цена` больше `0,01` отмечается предупреждением. Для файлов перчаток цена поставщика не нужна;
- для веса сотрудник явно указывает строку/единицу и кг/г. Пары всегда означают пары, без деления на два; места и пар в месте могут заполнить недостающее значение без округления. Неизвестное остаётся неизвестным;
- URL фото хранятся как текст и **не скачиваются автоматически**. Поэтому SSRF-защита загрузчика URL на этом этапе не требуется и сетевых запросов к URL нет;
- при повторной загрузке того же файла система предупреждает о совпадении и не добавляет строки сама. Явная замена выполняется одной транзакцией только после подтверждения.

Интерфейс этапа 2 состоит из двух экранов: «Колонки и строки» (источник, выпадающие назначения и исключение строк) и «Проверка и сохранение» (исправления, фото и применение).

### Ручной сценарий импорта

1. Войдите, создайте или откройте смету и сохраните её.
2. В блоке «Товары из XLSX» выберите `.xlsx`.
3. На первом экране выберите лист, строку заголовков и начало данных. Назначение каждой колонки выбирается прямо в её шапке через выпадающий список; ненужные колонки оставьте «Не использовать».
4. В этой же таблице оставьте или уберите строки кнопкой «×». На втором экране исправьте ячейки, добавьте строки и фотографии.
5. Нажмите «Сохранить черновик», обновите страницу и убедитесь, что назначения и правки восстановились. Итоговую строку оставьте выключенной; выбранную ячейку можно перенести в «общий вес партии» с указанием единицы и источника.
6. После устранения блокирующих ошибок нажмите «Применить и завершить этап». Нормализованная таблица будет показана в фиксированном порядке: №, название, брутто/нетто, количество/единица, цена, валюта, сумма, артикул, перевод, материал, характеристики, фото, дополнительные поля.
7. Для возврата нажмите «Редактировать исходную таблицу»: открывается сохранённый рабочий черновик, а не реконструкция из нормализованных товаров.
8. Для повторного того же файла выберите явную замену; без неё существующая таблица не меняется.

Черновик хранится на сервере через `GET/PUT /api/imports/:id/workspace`; применение выполняется через `POST /api/imports/:id/workspace/apply` одной транзакцией. Исходный файл не перезаписывается.

Удалить смету можно кнопкой `×` в списке смет после подтверждения. Серверный маршрут `DELETE /api/estimates/:id` проверяет владельца и удаляет связанные импорты, товары и закрытые файлы.

## Классификатор ТН ВЭД и ставки (этап 3)

Экран «ТН ВЭД» выполняет поиск по коду/описанию и дате оценки, показывает период действия, версию, источник и отдельные документы (примечание, пояснение, исключение). Группировочные коды явно отмечены и не принимаются как конечные для проверки правил. DEMO-записи имеют отдельную метку и не выдаются для обычного использования без явного `allowDemo=true`.

Импорт выполняется после предварительного отчёта:

```powershell
POST /api/catalog/import/preview
POST /api/catalog/import/apply
```

JSON-контракт: `{ "version": {"versionKey":"...", "datasetKind":"real|demo", "source":"...", "sourceDate":"YYYY-MM-DD", "status":"active|archived"}, "codes": [{"code":"000123","hierarchyLevel":6,"parentCode":"","officialDescription":"...","isGroup":false,"validFrom":"YYYY-MM-DD","validTo":"YYYY-MM-DD","source":"..."}], "documents": [{"code":"000123","parentCode":"","docType":"note|explanation|exception","title":"...","content":"...","source":"...","validFrom":"YYYY-MM-DD"}], "rules": [{"code":"000123","ruleKey":"...","paymentType":"...","rateType":"ad_valorem|specific|combined|fixed|unknown","value":5,"currency":"","unit":"%","operation":"","conditions":{},"validFrom":"YYYY-MM-DD","source":"..."}] }`.

Поддержан также компактный CSV с заголовком `versionKey,datasetKind,source,code,hierarchyLevel,parentCode,officialDescription,isGroup,validFrom,validTo` (строки создают коды; документы и правила для CSV добавляются JSON-импортом). Проверяются типы, даты, дубли, пересечения правил, обязательный источник и положительность/неизвестность значения. Повтор того же `versionKey` идемпотентен, старые версии не удаляются. Неизвестная ставка задаётся `rateType=unknown`, а не нулём; истинный ноль также требует источника.

Проверка применимости: `POST /api/catalog/rules/applicable` с `{code,date,conditions,allowDemo}` возвращает `ok`, `ambiguous`, `group_code`, `demo_blocked` или `not_found`. При нехватке условий перечисляются ключи `missing`.

## Предварительный расчёт растаможки (этап 3)

Для файлов поставщика без цен в рабочем черновике доступны отдельные поля «Пары», «Места» и «Пар в месте». Они добавляются миграцией `000013_glove_quantities`; перед запуском backend на существующей базе выполните `docker compose run --rm migrate`.

В открытой смете нажмите «Расчёт растаможки». Экран создаёт расчёт одной партии (одной декларации) и сохраняет его сервером через `GET/PUT /api/estimates/:id/calculation`. Позиции берутся из подтверждённого импорта Excel; цены поставщика не требуются.

Основные поля строки: пары, места, пар в месте, брутто/нетто в кг, ИТС карточки перчаток, стоимость в USD и цена пары. Пары не делятся на два. Если нет нетто, сервер рассчитывает его как `брутто − места × вес упаковки`, сохраняет с единицей `kg` и источником `calculated`; значение упаковки по умолчанию 0,3 кг редактируется. Введённое или импортированное с известной единицей нетто нормализуется в кг и не перезаписывается. Неизвестная единица не принимается за кг; отрицательное нетто и нетто больше брутто блокируют строку. ИТС, название и ставки из справочника фиксируются снимком и не меняют старые расчёты при последующем редактировании справочника.

В таблице цена пары округляется максимум до четырёх знаков после точки (`0.0288`) и именно это округлённое значение используется как источник стоимости строки: `цена пары × количество пар`. Поэтому для 96 000 пар стоимость при цене `0.0288` равна `2764.80`, а не `2763.00`. Стоимость, доставка, пошлина/НДС и итоговые суммы отображаются до двух знаков; это внутренняя политика отображения, а не официальное таможенное правило.

Доставка задаётся в одном из явно выбранных режимов: «По вагонам» (`количество × тариф`) или «Общая сумма» (ввод USD). В активном режиме пустое поле является ошибкой, а явный `0` допустим. Введённая сумма — это стоимость доставки всей партии, а не цена каждой строки. Затем она автоматически распределяется по положительному брутто включённых строк; распределённые строки не являются источником общей суммы. Остаток округления детерминированно попадает в последнюю участвующую строку. Поэтому `840 USD × 447,88 = 376 219,20 KZT`, и сумма строк в KZT совпадает до тиына. Для нового расчёта при первом явном выборе режима включение распределённых долей в таможенную базу включается по умолчанию; это можно изменить флагом строки. Сбор задаётся один раз в KZT и распределяется по таможенной стоимости для предварительной базы НДС. Процентные, специфические и комбинированные ставки читаются только из выбранного снимка справочника; неизвестные/неподдерживаемые значения показываются как «Требуется проверка», а не как 0.

Переключатель строки называется «Добавлять доставку к таможенной стоимости». Он влияет только на базу платежей; в общих расходах вся доставка учитывается один раз. Программа не определяет автоматически расходы до/после границы и не утверждает юридическую применимость включения. Старый расчёт без сохранённого режима доставки помечается как legacy/unknown; при следующем сохранении оператор должен выбрать режим, иначе прежняя распределённая сумма не будет использована.

Если в уже сохранённом расчёте режим доставки задан, но показатель «В таможенной стоимости» равен `0`, это старый снимок с выключенными флагами строк. В обновлённом экране нажмите «Включить доставку в базу для всех», затем «Сохранить и пересчитать». Историческая ревизия не меняется автоматически; после явного сохранения появится новая ревизия с текущей формулой.

При включённом флаге в базу строки добавляется её округлённая доля доставки в KZT; это согласует базу с показанной суммой распределения. При выключенном флаге доставка не входит в таможенную стоимость, но остаётся отдельным расходом партии. На экране и в Excel отдельно показаны «Таможенные платежи» (`пошлина + НДС + сбор`), «Доставка» и «Всего из кассы» (`таможенные платежи + доставка`); стоимость самих товаров в последний показатель не входит. При неположительном или неполном брутто автоматическое распределение блокируется до исправления данных или ручного распределения.

Параметр `feeIncluded` сохранён только для совместимости API и не является переключателем: в действующей предварительной формуле сбор всегда распределяется один раз и входит в базу НДС. Явное значение `false` отклоняется сервером, чтобы настройка не выглядела рабочей, когда она не поддерживается.

### Ручная проверка доставки

1. Откройте смету с подтверждёнными товарами и перейдите в «Расчёт растаможки». Если таблица ещё пустая после импорта, нажмите «Загрузить подтверждённые товары».
2. Выберите «По вагонам», укажите `2` вагона и тариф `420 USD` (или выберите «Общая сумма» и введите `840`). Поле общей суммы означает всю партию.
3. Убедитесь, что у включённых строк появились доли доставки, их сумма равна `840,00 USD / 376 219,20 KZT`, а флаг «Добавлять доставку к таможенной стоимости» включён для нового расчёта. Снимите флаг у строки только если доставка уже входит в её стоимость.
4. Нажмите «Сохранить и пересчитать», обновите страницу и сравните три итога: таможенные платежи, доставка и всего из кассы. Кнопка «Экспорт Excel» должна содержать те же значения сохранённого снимка.
5. Для проверки перераспределения измените брутто или состав включённых строк и сохраните снова: автоматические доли строятся заново, а сумма партии остаётся неизменной. При пустом/нулевом брутто сервер покажет блокирующую ошибку вместо распределения по догадке.

Курсы USD/KZT и EUR/KZT, дата оценки и происхождение вводятся сотрудником. Тариф вагона и вес упаковки — предварительные настройки, не официальные тарифы. Наличные и остаток отображаются в USD; товары в наличные не включаются. Выбор карточки для нескольких строк выполняется явно через кнопку «Выбрать из базы для выбранных».

Ограничения текущей версии: экспорт помечен как `PRELIMINARY` и содержит URL фотографий (встроенные приватные изображения остаются доступны только через авторизованный API); автоматическая загрузка ставок с сайтов и официальная проверка кодов ещё не подключены. Реальные ставки нужно внести оператором и проверить по источнику. Расчёт можно сохранять неполным, при этом в таблице видны конкретные предупреждения.

## AI provider (TN VED suggestion prototype)

The server sends an explicit, per-product analysis request to the configured AI provider. New installations use Anthropic's Messages API with the active Claude Haiku 4.5 model `claude-haiku-4-5-20251001`; Gemini remains available as an optional provider. The result is only a suggestion and does not verify the existence or legal validity of a TN VED code, customs duty, VAT, or any other rate. No request is sent automatically for all imported rows.

Set these variables in the server `.env` (or in the `backend` service environment in Docker Compose):

```dotenv
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=put-your-server-key-here
ANTHROPIC_MODEL=claude-haiku-4-5-20251001

# Optional alternative:
# AI_PROVIDER=gemini
GEMINI_API_KEY=put-your-server-key-here
GEMINI_MODEL=gemini-3.8-flash
```

The selected provider key is never exposed to the browser and is not logged. Leave the selected provider's key empty until it is configured; the API then returns a clear configuration error rather than DEMO data. Do not commit a real key.

After opening a saved product, click **Analyze** in the TN VED panel. The request includes only fields currently filled in the product plus optional extra characteristics. The response shows the proposed code, explanation, alternatives, missing characteristics and questions, with the label “Предложено ИИ — не проверено”. A code is applied only after an explicit user click; an existing manually selected code is not overwritten. Editing product characteristics marks the previous analysis for re-check.

API endpoints (authenticated): `POST /api/products/:id/ai-analyze` with `{ "extra": "..." }`, `GET /api/products/:id/ai-analysis`, and `PATCH /api/products/:id/tnved` with `{ "code": "1234567890" }` (empty code clears it). Inputs are limited to 32 KiB, one provider request is sent per explicit click (there are no automatic retries), the request has a 25-second timeout and the complete interaction a 40-second deadline, with a one-request-per-second user cooldown. Use the retry button only when you explicitly want to send a new request. Invalid JSON or non-10-digit codes are rejected server-side.

For the per-product dialogue the authenticated endpoints are `GET /api/products/:id/ai-dialog`, `POST /api/products/:id/ai-dialog/messages` and `POST /api/products/:id/ai-dialog/apply`. A message request contains `message`, a client-generated `clientRequestId` and up to four existing product image IDs. The server stores the user message before calling the provider, returns a saved failed message on provider errors, and treats a repeated request ID as the same request. Dialogue context is limited to the current product, IDs of its private images, the latest analysis and the last 50 completed messages; it never includes the whole estimate or workbook. The current text adapters do not send binary image bytes to the provider; attachments are stored, access-checked and shown in the dialogue. Proposed characteristic changes are applied only after an explicit action and mark the previous analysis for re-check.
Candidate catalog fields are added by the server: `verified` is returned only for a matching current non-DEMO catalog row, while unavailable/DEMO data remains `not_verified`; the model's position name is never presented as an official description.

The prototype sends text fields and a photo URL when present; it does not upload binary product images to Gemini. Image files remain in the existing private storage.

Manual smoke check: configure the key, start the stack, sign in, open an imported product, run Analyze, inspect the result and click Apply only if appropriate. For tests without a paid request use the mocked HTTP tests; a live call is not considered verified until a real key is supplied.

Official references checked on 2026-09-14: Anthropic model lifecycle documentation (https://docs.anthropic.com/en/docs/about-claude/model-deprecations) and Messages API documentation (https://docs.anthropic.com/en/api/messages); Google's Gemini Generate Content documentation remains applicable when `AI_PROVIDER=gemini`.

## Справочник ТН ВЭД (операторские записи)

В верхней навигации доступна отдельная страница «Справочник ТН ВЭД». В первой версии используется категория «Перчатки»: сотрудник вручную добавляет понятное название, 10-значный код и синонимы на русском, китайском и английском. Поиск работает по коду, названию и синонимам; статус можно фильтровать как «Требует проверки» или «Проверено оператором».

Справочник хранится в таблице `tnved_directory_entries` как операторский overlay поверх неизменяемых версий классификатора. Это не официальное описание и не подтверждение актуальности кода. Один код может иметь несколько названий; дубликат активной пары «код + категория + название» отклоняется (HTTP `409`). Удаление заменено архивированием, поэтому история сохраняется. Изменения записи не обновляют уже сохранённые товары и сметы.

В карточке импортированного товара кнопка «Выбрать из справочника» ищет активные записи по названию и синонимам. Применение выполняется только после явного подтверждения сотрудника. В товар сохраняется снимок выбранной записи (`tnved_directory_snapshot`) и её идентификатор, поэтому последующие правки справочника не меняют старую смету. Неуказанная ставка отображается как «Не указана», `0` хранится отдельно и требует осознанного ввода. Для пошлины доступны процентная, за единицу и комбинированная «не менее» ставки; для НДС — процентная, освобождение с основанием или неизвестная. Значение `12` означает 12%; принимаются точка и запятая. ИТС компании хранится отдельно и используется в формуле `USD = ИТС × вес нетто (кг)`, цена пары вычисляется только в контексте партии. Даты действия и источник ставки сохраняются отдельно для пошлины и НДС.

API (требует сессию): `GET /api/tnved-directory?q=&category=Перчатки&status=all&includeArchived=false`, `POST /api/tnved-directory`, `PATCH /api/tnved-directory/:id`, `POST /api/tnved-directory/:id/copy`, `POST /api/tnved-directory/:id/archive`, `POST /api/tnved-directory/:id/restore`. Для выбора записи товаром используется `POST /api/products/:id/tnved-directory` с `entryId`. Поля `duty` и `vat` структурированы (`type`, `percent`, `amount`, `currency`, `unit`/`basis`, `checkedAt`, даты действия, источник); неизвестное значение передаётся пустыми полями, а не нулём.

Чтобы добавить первую карточку: войдите, откройте в верхней навигации «Справочник ТН ВЭД» → «Добавить запись», выберите категорию «Перчатки» и заполните русское название и 10 цифр кода. Китайское название и ИТС можно указать отдельно (например, `0,65`); пошлину и НДС оставьте «Не указана/Не указан», если источник ещё не проверен. Сохраните запись со статусом «Требует проверки». Код `4015190000` из примера пользователя является только предоставленным значением и не считается подтверждённым автоматически.
